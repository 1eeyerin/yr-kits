# Agents 지침 운영 기준

프로젝트 규칙을 추가하거나 수정할 때 이 문서를 기준으로 판단한다.

## AGENTS.md와 .agents/docs의 역할

- `AGENTS.md`는 짧은 진입점이다.
- 상세 규칙은 `.agents/docs/*.md`에 둔다.
- `AGENTS.md`에는 모든 세부 규칙을 길게 쓰지 않는다.
- 새 작업 유형이 생기면 `AGENTS.md`에는 "어떤 문서를 읽을지"만 추가한다.

## AGENTS.md를 수정해야 하는 경우

아래에 해당할 때만 `AGENTS.md`를 수정한다.

- 레이어 구조가 바뀌는 경우
- 새 핵심 폴더가 생기는 경우
- 모든 작업에 영향을 주는 금지 규칙이 생기는 경우
- 새 문서가 생겨 작업 유형별 읽기 규칙에 추가해야 하는 경우
- pnpm 워크스페이스, 패키지 경계, Zeplin처럼 전역적으로 중요한 기준이 바뀌는 경우

아래는 `AGENTS.md`가 아니라 `.agents/docs`에 쓴다.

- 특정 기술 사용법
- 세부 네이밍 규칙
- 커밋/PR 상세 규칙
- 리뷰 체크리스트
- 특정 도메인 작업 절차
- 예시 코드와 긴 설명

## docs 작성 기준

`.agents/docs`에는 프로젝트 작업 지침서를 둔다.

문서가 필요한 경우:

- 같은 판단을 반복해서 하게 되는 경우
- 에이전트가 자주 헷갈리는 구조/규칙이 있는 경우
- 작업 전에 반드시 확인해야 하는 체크리스트가 있는 경우
- 특정 기술 사용 방식이 이 프로젝트에서 고정되어 있는 경우

파일명은 `kebab-case.md`를 사용한다.

권장 frontmatter:

```md
---
title: 문서 제목
description: 문서가 다루는 내용
when_to_read: 언제 이 문서를 읽어야 하는지
scope:
  - packages/**
  - website/**
tags: [tag]
---
```

## commands 작성 기준

`.agents/commands`에는 반복 작업을 위한 명령 템플릿을 둔다.

추가 기준:

- 작업 순서가 반복되는 경우
- 특정 문서를 먼저 읽어야 하는 작업인 경우
- 출력 형식이 정해져 있으면 실수가 줄어드는 경우

커맨드는 반드시 현재 프로젝트 구조를 기준으로 작성한다.
다른 프로젝트명, 절대경로, 외부 레포 전용 규칙을 남기지 않는다.

## skills 작성 기준

`.agents/skills`에는 재사용 가능한 스킬을 둔다.

추가 기준:

- 특정 기술이나 도메인에 대한 독립적인 지침이 필요한 경우
- 다른 프로젝트에서도 재사용 가능한 범용 지식인 경우
- `docs`보다 큰 워크플로 또는 참고 자료 묶음이 필요한 경우

프로젝트 전용 규칙은 가능하면 `.agents/docs`에 둔다.

## 수정 전 체크리스트

- 이 내용이 전역 규칙인가, 특정 작업 문서인가
- 짧게 라우팅할 내용인가, 자세히 설명할 내용인가
- 기존 문서에 추가하면 되는가, 새 문서가 필요한가
- 다른 프로젝트명이나 절대경로가 남아 있지 않은가
- `AGENTS.md`와 중복 설명이 생기지 않는가
